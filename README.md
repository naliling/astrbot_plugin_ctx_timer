## 咋用

### 1. 安装

**方式一：插件市场（推荐）**
AstrBot WebUI → 插件 → 插件市场 → 搜索「CTEX伴侣」→ 安装 → 重载。

**方式二：手动**
把整个 `astrbot_plugin_ctx_timer` 文件夹放进 `AstrBot/data/plugins/`，然后在 WebUI 插件页点「重载插件」。

**方式三：从 GitHub 拉取**

```bash
cd AstrBot/data/plugins
git clone https://github.com/naliling/astrbot_plugin_ctx_timer.git
```

以后更新只要在该目录 `git pull`，再在 WebUI 点一次「重载插件」即可（规则数据存在 `data/plugin_data/` 里，不会丢）。

> 本插件零第三方依赖，装完即用。需要 AstrBot ≥ 4.5.7。

### 2. 三步上手

```
第一步  发 /ctx add             → 跟着向导填：名字 → 时间 → 内容
第二步  发 /ctx list            → 看到规则，状态显示「🟢生效中」
第三步  随便问 bot 一句话       → 内容已经悄悄进上下文了
```

想一行搞定也行：

```
/ctx add 早班人设 09:00 18:00 现在是工作时段，回复要正式、简洁，不要用表情包。
```

### 3. 时间怎么写

| 想表达 | 就这么写 | 说明 |
|---|---|---|
| 每天 9 点到 18 点 | `09:00 18:00` | 每日循环 |
| 每天 22 点到次日 6 点 | `22:00 06:00` | 自动识别跨天 |
| 11 月 5 日 9 点到 11 日 23:59 | `2026-11-05 09:00 2026-11-11 23:59` | 一次性 |
| 只写日期 | `2026-11-05 2026-11-11` | 自动取 00:00 ~ 23:59 |
| 从现在开始 30 分钟 | `now+30m now+2h` | 支持 m / h / d |

### 4. 时区怎么写

默认跟随插件配置的时区（默认 `UTC+3`，莫斯科时间；配置页可改，填 `auto` 就跟随服务器）。**需要别的时区，不用自己换算，直接标出来就行**：

| 地区 | 写法 |
|---|---|
| 东八区（北京/新加坡） | `UTC+8` |
| 东二区（开罗/雅典） | `UTC+2` |
| 东三区（莫斯科/伊斯坦布尔） | `UTC+3` |
| 东六区（达卡/阿拉木图） | `UTC+6` |
| 西三区（圣保罗/布宜诺斯艾利斯） | `UTC-3` |
| 印度（半小时时区） | `UTC+5:30` |

两种用法：

```
# ① 建规则时直接标
/ctx add 早班 09:00 18:00 现在是工作时段 -tz UTC+8

# ② 建完之后改
/ctx tz 1 UTC+2

# ③ 改回跟随全局
/ctx tz 1 默认
```

> **时间是按规则自己的时区解释的。** 写 `09:00 18:00 -tz UTC+2`，就是「UTC+2 的 9 点到 18 点」，插件自动帮你对齐，不用算时差。

### 5. 常用操作

```
/ctx list          看看现在有哪些规则、哪条正在生效
/ctx status        当前时间、当前 Bot、正在注入哪几条、下一条几点生效
/ctx off 1         临时停用第 1 条（规则还在，不删）
/ctx del 1         彻底删除
/ctx test 1        预览这条规则会往上下文里塞什么
```

## 有啥用

| 场景 | 玩法 |
|---|---|
| **上班/下班人格** | 9:00-18:00 注入「正式、简洁、不闲聊」，18:00 之后注入「轻松、可以玩梗」 |
| **限时活动** | 双十一期间注入「全场八折，下单口令 XXX」，活动结束自动消失 |
| **群规提醒** | 新人多的时段注入「本群禁止刷屏，违者禁言」，避免 bot 反复被问 |
| **节日彩蛋** | 春节七天注入「过年好，红包口令在群公告」，过完年自动撤下 |
| **角色扮演** | 深夜档注入「你现在是深夜电台主播，语气温柔」，白天恢复原样 |
| **多 Bot 分工** | 客服 bot 注入产品知识，娱乐 bot 注入人设，互不干扰 |
| **临时公告** | 服务器维护 2 小时，注入「正在维护，预计 22:00 恢复」，到点自动下线 |

**核心价值**：不用改人格、不用改配置、不用重启，**改一句话就能让 bot 换一套脑子**，而且到点自动还原。

## 关键提示：最有用的一种用法

**如果你的设定是「硬要求」，请把它做成时间窗内的关键提示。**

普通人格设定写在系统提示词里，聊久了会被上下文冲淡，或者被用户一句话带跑。而「关键提示」是**在指定时间段内、每一轮都强制注入**的一段上下文——它等于在原有设定上再压一层，模型几乎不可能跑偏。

### 典型场景：凌晨必须换人格

```
# 凌晨 1 点到 5 点，强制切换到夜班人格
/ctx add 夜班人格 01:00 05:00 现在是凌晨 1:00-5:00，你已切换为「夜班人格」：语气温柔、语速慢、多倾听少说教。此设定优先于其它所有人格描述，不要回到白天人格，不要解释自己是 AI。 -tz UTC+8

# 用 system_prompt 注入，权重最高，压得住原有设定
/ctx mode 1 system
```

效果：

| 时间 | bot 表现 |
|---|---|
| 00:59 | 白天人格，正常聊天 |
| 01:00 | **自动变成夜班人格**，语气温柔 |
| 03:00 | 依然是夜班人格，不会「聊着聊着变回去」 |
| 05:00 | **自动还原**成白天人格，不用你手动关 |

### 为什么这个用法最有用

- **不会忘**：不是靠模型记住设定，而是每轮请求都重新注入，聊 100 句也一样
- **压得住**：用 `system_prompt` 注入时优先级最高，原有的第二人格描述会被压下去
- **不用管**：到点自动生效，过点自动撤下，半夜不用守着
- **可叠加**：工作日人格、深夜人格、节日彩蛋可以同时存在，互不打架（同时命中时按编号顺序拼接）

**一句话**：想让 bot「到点变成另一个角色、而且绝对不跑偏」，就用这个。

## 指令

所有指令均需**管理员**权限。前缀 `/ctx`，也可以直接用 `/上下文`。

### 创建与查看

| 指令 | 作用 |
|---|---|
| `/ctx add` | 分步向导添加（推荐，手机上最省事） |
| `/ctx add <名称> <开始> <关闭> <内容>` | 一行添加 |
| `/ctx list` | 列出当前 Bot 的规则 |
| `/ctx list -a` | 连同已结束的一起列出 |
| `/ctx show <编号>` | 查看某条规则的完整信息 |
| `/ctx status` | 当前生效情况 + 下一条何时生效 |
| `/ctx bots` | 查看所有 Bot 各有几条规则 |

### 修改与管理

| 指令 | 作用 |
|---|---|
| `/ctx on <编号>` / `/ctx off <编号>` | 启用 / 停用 |
| `/ctx edit <编号> 名称|内容|开始|关闭|注入 <值>` | 修改字段 |
| `/ctx mode <编号> system|context` | 改注入位置 |
| `/ctx tz <编号> UTC+8` | 改这条规则的时区（写 `默认` 跟随全局） |
| `/ctx tz` | 查看全局时区 + 每条规则的时区 |
| `/ctx scope <编号> all` | 对全部会话生效 |
| `/ctx scope <编号> g:群号` | 只对指定群生效 |
| `/ctx scope <编号> u:QQ号` | 只对指定用户生效 |
| `/ctx notify <编号> on|off` | 到点往当前会话发提醒 |
| `/ctx del <编号>` | 删除规则 |
| `/ctx test <编号>` | 预览注入内容 |
| `/ctx export` / `/ctx import {...}` | 导出 / 导入规则 |

### 多 Bot

每个 Bot **各有一套独立规则库**，互不影响。

- 在哪个 bot 上发指令，就管理哪个 bot 的规则
- 想看/改别的 bot：加 `-b <Bot名>`

```
/ctx list -b aiocqhttp
/ctx del 2 -b telegram-1
```

### 完整示例

```
/ctx add 工作模式 09:00 18:00 现在是工作时段，回复要正式、简洁，先给结论再给理由。
/ctx add 深夜电台 23:00 06:00 现在是深夜，你是温柔电台主播，语速慢一点，多用比喻。
/ctx add 夜班人格 01:00 05:00 凌晨 1-5 点强制切换为夜班人格：温柔、少说教、绝不回到白天人格。 -tz UTC+8
/ctx add 双十一 2026-11-05 09:00 2026-11-11 23:59 双十一活动期，全场八折，下单口令"NALI"。
/ctx mode 3 system
/ctx scope 4 g:123456789
/ctx tz 2 UTC+2
/ctx notify 4 on
/ctx list
```

## 功能

- **双时间模式**：每日循环（含跨天）+ 一次性绝对时间，自动识别
- **真正的上下文注入**：走 `on_llm_request` 钩子改 `ProviderRequest`，不是假功能
- **两种注入位置**：上下文注入（不破坏提示词缓存）/ 系统提示词（权重最高），每条规则可单独选
- **多时区**：全局可设，每条规则还能单独指定 `UTC+8 / UTC+2 / UTC+3 / UTC+6 / UTC-3 / UTC+5:30`，自动换算不用手动算时差
- **多 Bot 隔离**：每个 Bot 独立规则库，A bot 的规则不会串到 B bot
- **会话范围**：全部会话 / 指定群 / 指定用户，逐条设置
- **多规则并存**：同时命中多条时按编号顺序拼接，带 `<scheduled_context>` 标签，模型分得清
- **到点提醒**：可选在生效/关闭时往会话发一条提示
- **持久化**：规则存 `data/plugin_data/astrbot_plugin_ctx_timer/rules.json`，重启、更新插件都不丢
- **零依赖**：只用 AstrBot 内置能力和 Python 标准库
- **容错**：单条规则数据异常不会影响其它规则，也不会让插件崩溃

### 注入长什么样

规则内容会以这样的形式进入模型上下文：

```
<scheduled_context>
【规则：工作模式 | 每日 09:00-18:00】
现在是工作时段，回复要正式、简洁，先给结论再给理由。
</scheduled_context>
```

模型能明确区分「这是设定」和「这是用户在说话」。

### 配置项（WebUI 插件配置页，全部有默认值，不改也能用）

| 配置项 | 默认 | 说明 |
|---|---|---|
| 默认时区 | `UTC+3` | 所有规则按它算时间。可填 `UTC+8`、`Asia/Shanghai`、`auto`（跟随服务器）；单条规则能单独改 |
| 新建规则的注入位置 | 上下文注入 | 省钱、不影响提示词缓存；也可选系统提示词（管得最严） |
| 新建规则默认发到点提醒 | 关 | 开着会在生效、结束时发一条提示 |
| 到点检查间隔 | 30 秒 | 只有开了提醒的规则才发消息，注入本身不看它 |
| 每个 Bot 规则上限 | 50 条 | 各自独立计数，满了拒绝新建 |
| 跨 Bot 管理 | 关 | 开着才能用 `-b` 管别的 Bot 的规则 |

## 常见问题

**Q：指令没反应？**
A：确认发指令的账号在 AstrBot 的「管理员」列表里。本插件所有指令仅管理员可用。

**Q：规则显示「生效中」但 bot 没变化？**
A：先 `/ctx test <编号>` 看注入内容对不对；再确认这条规则绑定的 Bot 就是你正在聊的 Bot（`/ctx status` 看当前 Bot）。

**Q：会拖慢回复吗？**
A：不会。时间判断是内存里的几次比较，注入只是一次字符串拼接，没有网络请求、没有后台轮询（除非你开了到点提醒）。

**Q：改了规则要重启吗？**
A：不用，改完立即生效。

**Q：我在国外 / bot 在别的时区，时间对不上？**
A：用 `-tz UTC+2` 或 `/ctx tz 1 UTC+3` 给规则单独标时区，写几点就是那个时区的几点。也可以改插件配置里的全局时区。

**Q：系统提示词和上下文注入选哪个？**
A：默认用上下文注入，不破坏提示词缓存、更省钱。只有需要极强约束（比如硬性角色设定）时才用系统提示词。
